1. Objective

Allow users to print vehicle service reminder stickers from a Work Order (WO) after servicing a vehicle. The sticker must display the current mileage and the recommended next service mileage and date based on the configuration of the serviced items and services.

The system must support predefined sticker templates, manual editing according to system settings and user permissions, automatic sticker printing after invoice confirmation, and service package configuration.

2. User Story

As a POS user,
I want to print a service reminder sticker for the items and services performed on a vehicle,
So that the customer can identify when the vehicle is due for its next service based on mileage or time.

3. Item Form Configuration

Add the following fields to the Item form for both Product and Service item types.

FieldDescriptionValidation
Next Service Reminder Period The period after which the vehicle should return for the next service Must be a positive value when configured
Next Service Reminder Period Unit Unit for the period, such as Days, Weeks, or Months Required when Next Service Period is entered
Next Service Reminder (KM/Miles) Mileage interval for the next service Must be a positive value when configured
Mileage Unit KM or Miles, based on the company's configured unit Must be consistent with vehicle mileage
Auto Print Service Sticker Determines whether the item/service automatically triggers sticker printing Yes/No; default No

The system must allow mileage-based reminders, date-based reminders, or both.

Business Rules

  1. The Next Service Period and Next Service KM/Miles fields are optional at item definition level.
  2. The user must have the appropriate permission to create or modify these values.
  3. Changes to item configuration must not retroactively change stickers already printed or historical work orders.
  4. For date-based reminders, the next service date is calculated from the applicable service completion date using the configured period.
  5. For mileage-based reminders, the next service mileage is calculated from the current vehicle mileage plus the configured mileage interval.

4. Sticker Printing from the Work Order

Add an action to the Work Order menu:

Service Reminder Sticker

The action allows the user to print reminder stickers for eligible items and services included in the Work Order.

Workflow

  1. The user opens a Work Order for a vehicle.
  2. The user selects Service Reminder Sticker.
  3. The system retrieves the eligible products and services from the Work Order - item/service cart.
  4. The system identifies items configured for sticker printing and retrieves their next-service settings.
  5. The system displays the available sticker templates.
  6. The user selects the sticker template and the eligible services to print, subject to the Auto Print rules.
  7. The system calculates the next service mileage and date.
  8. The system validates the configuration, permissions, and required information.
  9. The system displays a preview where supported.
  10. The user confirms printing.
  11. The system prints the stickers using the configured printer and records the print history.

5. Sticker Template Selection

The system must display sticker template configured for the company or applicable branch.

Business Rules

  1. Only active and compatible templates may be selected.
  2. The system must respect the user's branch and printer permissions.
  3. The user may select a template for manual printing when the item is eligible for manual selection.
  4. Automatically printed stickers must use the configured default template or another template selected by the applicable automatic-print configuration.
  5. If no eligible template or compatible printer is available, the system must display a clear message and must not report the sticker as successfully printed.

6. Manual Data Entry and Editing Permission

[AllowManualServiceStickerDataEntry]

When the Permission Is applicable

  1. The system retrieves the Next Service Period and Next Service KM/Miles values from the item/service definition.
  2. The system calculates the next service date and mileage.
  3. The user may edit the Reminder Item data before printing.
  4. If no configuration exists for the selected item/service, the system must notify the user that configuration is required.
  5. Users with the appropriate item-maintenance permission may open the item definition and configure the missing values.
  6. Users without item-maintenance permission must not be allowed to change the item definition.
  7. If the user changes the sticker data without modifying the item definition, the changes apply only to the current sticker unless explicitly saved through the item-maintenance workflow.

When the Permission Is not applied

  1. The system retrieves and displays the configured item/service values.
  2. The calculated next service date and mileage must be read-only.

  3. If required configuration is missing, display:

    "Please configure the service sticker data for this item or service and set the required details to continue."

  4. The user must not proceed with printing a sticker that requires missing configuration.
  5. An authorized user may navigate to the item definition, configure the required values, save the changes, and retry printing.

7. Automatic Sticker Printing

Business Rules

  1. Automatic printing must occur only after the invoice confirmation process succeeds.
  2. The system must not print automatically when invoice confirmation fails or the invoice remains in Draft.
  3. The system must validate required mileage, service period, sticker template, printer availability, and item configuration before printing.
  4. If required data is missing, the system must report the issue and provide an appropriate corrective action.
  5. Mark the sticker as printed.
  6. Authorized users may reprint a sticker through a controlled reprint action, with the reprint recorded in the audit history.
  7. If one invoice contains multiple eligible services, the system must process all applicable sticker print jobs.

8. Service Package Handling

When a Work Order contains a Service Package, the system must evaluate the included products and services to determine the sticker data.

Priority Rules

  1. The system must inspect the package's included item and service details.
  2. Product-level configuration has priority over service-level configuration when both provide a value for the same reminder dimension.
  3. If the product does not have a configured value for a dimension, use the corresponding service configuration.
  4. For a package containing multiple eligible products/services, the system must calculate the applicable reminder values according to the defined priority and minimum-interval rules.

Minimum Interval Rule

Where multiple included items or services define a next-service interval, the system must use the shortest applicable interval for the reminder dimension being calculated.

For example: [Each Service will print separately]

Package ComponentNext Service KMNext Service Period
Engine Oil 5,000 km 6 months
Oil Filter 10,000 km 12 months
Oil Change Service 7,500 km 6 months

The package reminder must use the applicable product priority and minimum configured interval. In this example, the resulting reminder is 5,000 km or 6 months, assuming the values are applicable to the same service event.

The mileage and time intervals must be evaluated separately. The system must not treat the shortest mileage interval as automatically determining the shortest time interval.

9. Sticker Content and Calculation

Each printed sticker must contain the following details:

FieldDescription
Service Name The serviced item or service name, or the configured package/service label
Current Mileage The vehicle mileage recorded for the relevant Work Order or service event
Next Mileage Current Mileage + configured Next Service KM/Miles
Next Date Service completion date + configured Next Service Period

Calculation Rules

Next Mileage

Next Mileage = Current Mileage + Next Service KM/Miles

Next Date

Next Date = Service Completion Date + Next Service Period

  1. The system must use the latest valid mileage captured for the Work Order or service event.
  2. The system must validate that the mileage unit is consistent with the vehicle's configured unit.
  3. If the required current mileage is missing, the system must request it before printing a mileage-based reminder.
  4. If the service period is not configured, the system must not invent a next service date.
  5. If only mileage is configured, print the mileage reminder and leave the date absent or display an approved equivalent such as "Not configured."
  6. If only a time period is configured, print the date reminder and leave the mileage absent or display an approved equivalent.
  7. The sticker must not display misleading dates or mileage values when the relevant configuration is missing.

10. Permissions

Provide separate permissions for:

  • Print Service Sticker
  • Edit Service Sticker Configuration

The manual-entry setting does not grant item-maintenance permissions. Users must have the relevant permission to update item definitions.

11. Audit and Print History

The system must record:

  • Company and Branch
  • Work Order Number
  • Invoice Number
  • Vehicle and Plate Number
  • Item/Service
  • Sticker Template
  • Current Mileage
  • Next Mileage
  • Next Service Date
  • Print Type (Manual / Automatic / Reprint)
  • Printed By
  • Print Date and Time
  • Printer
  • Print Status and Failure Reason

The system must retain the sticker values used at print time so that later changes to item definitions do not alter historical print records.

12. Acceptance Criteria

  1. Next Service Period and Next Service KM/Miles are available on Product and Service item forms.
  2. The system validates configured intervals and associated units.
  3. The Work Order menu contains a Print Service Sticker action.
  4. Users can select from active, eligible sticker templates.
  5. The system allows manual data editing only when the user permissions allow it.
  6. When manual entry is disabled (Permission), configured sticker data is read-only.
  7. Missing configuration blocks printing when the required data is unavailable.
  8. Authorized users can maintain missing item/service configuration.
  9. Automatic sticker printing occurs only after successful invoice confirmation.
  10. Service packages use product-level priority, service-level fallback, and the applicable minimum interval rules.
  11. Printer errors clear messages.
